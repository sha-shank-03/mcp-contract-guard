# Architecture and limits

`python -m mcp_contract_guard` reads bounded JSON case/baseline files, launches an explicit argv, discovers a modern server, validates its bounded multi-page catalog, and either saves that catalog or checks explicitly supplied cases. `diff` compares two saved snapshots without starting a server. Execution is deterministic apart from process timing; there is no agent/model loop.

Output preflight resolves relative/absolute names, normalizes platform case rules, and uses same-file identity for existing paths. All outputs are checked against all case/baseline/diff inputs and other destinations before reading/launch and again before writing. Collision exits 2 and stays on the console. This is preflight, not an atomic filesystem guarantee. Input reads consume only the size limit plus one sentinel byte before decoding.

| Component | Responsibility |
| --- | --- |
| `__main__.py` | CLI, configuration, console and JSON output, exit codes |
| `runner.py` | Discovery/list/call sequence, request self-validation, catalog and case checks, coverage |
| `stdio.py` | Byte framing, correlation, finite request deadlines, bounded queue, stderr draining, child cleanup |
| `validation.py` | Schema policy and supervised local worker deadline |
| `_validation_worker.py` | Named pinned protocol definitions, schema meta-validation, instance validation |
| `common.py` | Constants, strict JSON, structural limits, diagnostic errors |
| `contracts.py` | Snapshot validation, exact drift, limited offline comparison |

The protocol pin is `2026-07-28`, commit `271ecc9accafdd9b83a3c869fa67c22953b2af80`; the exact schema digest is checked before server startup and within protocol validation workers. [Provenance](../vendor/mcp/2026-07-28/provenance.json) records the source URL, digest, byte count, date, and license. Schema validation selects named `$defs`; the upstream root contains definitions rather than a restrictive instance schema.

Each outgoing discovery/list/call request is checked against its protocol definition before transmission and carries the version, empty client capabilities, and identity in `params._meta`. Envelope checks enforce JSON-RPC 2.0, matching ID types/values, and exactly one result or error. Method result schemas and recognized result types are checked separately. A server's declarations are not trusted as authorization.

The [base protocol](https://modelcontextprotocol.io/specification/2026-07-28/basic) requires clients to treat an absent `resultType` as `complete`. The runner preserves raw-schema issues, defaults only a parsing copy, and validates that copy. Omission alone does not fail. Results select their definition by resultType: complete tool results use `CallToolResult`, not the permissive generated union that can match an incomplete result through its other branch. A valid input_required result is schema-checked then reported as unsupported coverage; no continuation occurs.

All JSON Schema defaults to Draft 2020-12; other dialects are unsupported. Schema documents are meta-validated before accepting the catalog. Fragment references and composition are supported within the limits; schema locations are distinguished from data in enum/const. The registry refuses external retrieval, and the preflight policy rejects non-fragment references. No icon/resource/media is fetched. `format` is annotation-only. The worker returns paths and keyword names without embedding instance values in messages.

Bounds: 1 MiB frames; receive queue 32; notifications 32 per run; default 10 catalog pages/1000 tools/1 MiB aggregate canonical tool-definition bytes; formatted snapshots and every JSON input at most 1 MiB; at most 100 cases; schema depth 32/nodes 10000; decoded JSON depth 64/nodes 100000; worker payload 2 MiB/response 64 KiB. Repeated names/cursors fail. Protocol/instance validation runs in a supervised process with a finite deadline, killed on timeout. These are harness policies, not MCP-mandated numeric limits.

Reader threads frame bytes and drain stderr without retaining text. A separate writer prevents blocked stdin from blocking the controller. Request expiry attempts cancellation only after the original write completes, with a bounded write wait. The report distinguishes attempted/write-completed cancellation from server acknowledgment. No call is retried. Fatal prerequisite/wire/protocol failures abort; local case assertions collect failures and continue. Remaining cases after abort are skipped. Completed IDs and final queued messages are inspected so a duplicate final response cannot disappear into cleanup. Run budgets include baseline validation and are checked at boundaries; cleanup can add a bounded interval.

Cleanup closes stdin, waits, and terminates/kills the direct child if necessary. The report records PID, direct-child exit, forced termination, reader state, and stderr byte count. Descendant containment and process sandboxing are not provided. A server process can access the current user's files and credentials; the bundled fixture spawns no descendants and needs no credentials. Cleanup of arbitrary descendant-held pipe handles is not guaranteed.

The runtime does not persist raw server stdout/stderr transcripts or argument lists. Reports include explicit executed/skipped coverage and the caller's execution-mode label. The separate synthetic demo records CLI argv and console stdout/stderr for reproducibility; it does not record raw wire transcripts. The stdout reader can temporarily hold at most one frame plus a read chunk before rejecting an oversized pending frame. It inspects buffered bytes before deciding an observed process exit; this preserves a more specific framing failure.

Baseline tools/schemas and success-case inputs are validated before launch. Invalid baseline inputs exit 2 and cannot establish regression witnesses. After candidate discovery, exact input/output schema drift and catalog changes produce separate review findings. A rejected baseline-valid input establishes INPUT_REGRESSION. Candidate-valid successful data rejected by a baseline output schema establishes OUTPUT_REGRESSION. Error cases are excluded from success witness construction. Arrays retain order in exact schema comparison; no semantic schema containment is inferred. Descriptions/annotations are outside this comparison.

Cases declare success, tool_error, or rpc_error with an integer code. Intentional schema-invalid arguments require an explicit error expectation and allowInvalidArguments; the MCP request itself is always validated. Error results must still satisfy their wire schemas. Output-schema validation applies to successful results. Check/diff never mutate snapshots. Gate exits: 0 supported checks pass, 1 witness/server/case failure or unreviewed drift/incomplete coverage, 2 invalid invocation/configuration/local setup. Review-only drift reports review_required even when supplied cases pass. No universal compatibility proof is claimed.

`scripts/demo.py` uses the current absolute interpreter, pins every live scenario's label to local_mock_stdio, asserts intentional failure exits/findings, and checks baseline hashes after every command. It creates a new destination exclusively and saves exact receipts. Its assertions remain active under Python optimization. The wrapper has a 180-second overall budget and at most 40 seconds per CLI subprocess; the runtime keeps its own 30-second budget. A catastrophic wrapper timeout is failed evidence rather than a cleanup guarantee for orphan descendants.

Prepared CI mirrors the bounded test modules and demo on Windows/Linux with Python 3.11.9. Actions are commit-pinned; repository contents permission is read-only, checkout credentials are not persisted, and no account secret or deployment/publish action is configured. Hosted workflow/Linux execution remains unexecuted locally. Passing never proves security, model quality, general compatibility, or reliability outside these cases. Execution is modern stdio only; no HTTP/legacy/MRTR/SDK/packaging/provider expansion was added.
